# Groovy 策略性能实验

最终网络测量提交为 `ba6c32e03c16a3fdd60403f234573ae1c821eed2`，引擎测量提交为 `2e72e539492d119596ad5154446d5ee4c8f82b67`。其间只修改 Session 调度和 Store 扫描取消及回归测试，微基准涉及的引擎与 HugeSecurityManager 代码没有变化。2026 年 9 月 13 日在 `10.21.76.114` 完成引擎微基准和 RocksDB WebSocket 实验，各 20/20 轮有效，每种配置五轮。控制器成功退出，每轮均有完成标记且结果校验通过。

本实验衡量同一代码产物内的引擎和运行模式差异。A / B 使用当前代码中的 legacy 路径，没有另外构建纯升级基线，因此不能据此断言这次全部代码变更在 legacy 模式下没有性能影响。网络采用 AllowAll、单客户端串行请求，不属于完整业务性能或生产鉴权验收。

本轮普通请求的 C/B 请求速率变化为 -3.9% 至 +3.2%。Session 点查出现明显回退，C/B 请求速率下降 20.9%，P95 增加 30.3%；E/B 请求速率下降 30.7%，P95 增加 48.3%。Session 闭包查询的 C/B 速率也下降 6.2%。这些观察超出原设计部分数值参考线，当前不能给出所有查询无性能回退的结论，也没有完成原因归因。

## 配置与测量方法

| 代号 | 引擎 | HugeSecurityManager | JVM 模式 |
|---|---|---|---|
| A | 原引擎 | 未安装 | legacy |
| B | 原引擎 | 已安装 | legacy |
| C | 新策略 | 已安装 | combined |
| E | 新策略 | 未安装 | policy-only |

两组实验均按 `A B C E / E C B A / A B C E / E C B A / A B C E` 顺序运行，每轮单独 JVM，实验间没有重叠。JDK 为 Temurin 17.0.20，虚拟机有 8 vCPU、约 16 GiB 内存，JVM 固定 `-XX:ActiveProcessorCount=2`，保留项目模块开放参数。该主机运行其他服务，数据来自共享 KVM 环境，不能视为独占硬件结果。

引擎实验固定 512 MiB 堆，直接执行代码中的 `ScriptPolicyBenchmark`。热闭包和预编译 Store 条件各预热 3 秒、测量 10,000 次；冷编译使用 12 份不同源码，测的是预热 JVM 中的编译缓存未命中及首次求值，不包含进程启动。每轮冷编译只有 12 个样本，其 P95 对应该轮最大值，不用于稳定尾延迟估计。网络实验固定 1 GiB 堆，Server 与 Java driver 在同一 JVM 中通过 loopback WebSocket 通信，gremlin / worker / boss 池均为 1。每轮独立建立 RocksDB 图，含 5,000 个顶点和 10,000 条边。每种查询先执行 500 次，再测量 1,000 次，普通请求和 Session 分别记录，每次校验结果。

图创建、数据准备、启动和预热不计入计时。网络测得的是当前单并发请求速率，不能作为服务器最大吞吐。Session 是同一会话上的连续只读请求，复用会话事务状态，不含写入提交和失败恢复成本。网络完整有效序列共校验 240,000 次请求，其中 160,000 次进入测量。

下面的数值分别取五轮吞吐和单轮 P95 的中位数。P95 没有合并为跨轮总体百分位。逐轮 JSON 同时保留 P50、P95、P99 和吞吐，变化比例由未四舍五入的中位数计算。

原设计的业务预算为热查询吞吐下降不超过 5%、P95 增幅不超过 10%。本实验的身份、后端和并发范围不足以覆盖该预算的正式验收条件，表内变化用于定位候选路径，不能把局部通过解释为整体通过，也不能用 policy-only 的速度替代安全资格。

## 数据有效性与复现材料

首轮引擎尝试从测试子目录启动，冷编译受到 HSM 相对路径规则限制；首轮网络尝试把探针 classpath 目录放在启动根目录之外，产生可选类查找被拒绝的日志。这两组尝试均完整排除。另一次网络预验证发现 values() 结果的算术闭包需要显式 int 类型，四种配置统一改用同一显式转换表达式，原序列也完整排除。最终序列统一从源码根目录启动，网络探针类也位于该目录内；没有修改产品权限规则。
